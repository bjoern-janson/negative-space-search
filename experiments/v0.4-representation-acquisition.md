# v0.4 Preregistration — Representation Acquisition and Repair

Status: **preregistered before policy implementation**

## Question

Can an adaptive search process improve future evidence selection after a misdiagnosis by revising the representation it preserves from raw history, rather than receiving the useful causal distinctions as labels?

The target is representation repair, not a claim that negative-space terminology is uniquely responsible for performance.

## Raw history contract

Every learner receives the same raw episodes containing only:

```text
paired_measurements: 3 unlabeled numeric pairs
surface_hint: numeric
prediction
outcome
selected_action
timestamp
cost
resolving_probe
```

`resolving_probe` is the experiment that eventually resolved the episode. It is an observed action/outcome relation, not a semantic cause label.

The raw history does **not** contain labels such as:

```text
dependency failure
payoff drift
coordination failure
model mismatch
negative-space class
```

## Frozen candidate relation library

The representation-learning system may construct only these generic candidate distinctions:

### Unary surface tests

Applied to `surface_hint`:

```text
high      := value >= 0.60
low       := value <= -0.60
near_zero := abs(value) <= 0.15
```

Complexity cost: `1`.

### Pairwise relational tests

Applied independently to each of the three unlabeled measurement pairs:

```text
close         := abs(a - b) <= 0.08
far           := abs(a - b) >= 0.65
sign_disagree := a * b < 0 and min(abs(a), abs(b)) >= 0.10
```

Complexity cost: `2`.

The learner is not told which relation corresponds to which failure mechanism.

This is **representation selection/construction from a frozen generic relation library**, not unrestricted interface invention.

## Representation-learning rule

For each previously successful non-model-disrupting probe, select the candidate relation maximizing one-vs-rest balanced accuracy on accumulated resolved episodes, penalized by representation complexity:

```text
objective = balanced_accuracy - 0.01 * complexity
```

Deterministic tie-break order:

1. higher objective;
2. higher balanced accuracy;
3. lower complexity;
4. lexical candidate name.

The learner therefore has a parsimony pressure that can initially reward a cheap but spurious surface representation.

## Phase A — acquisition history

Six resolved episodes are provided: two for each known evidence action.

On this phase:

- `surface_hint` perfectly predicts which probe succeeds;
- stable relational distinctions are also present in the paired measurements;
- because surface features are cheaper, the preregistered learning rule should prefer the surface representation.

This deliberately rewards the wrong abstraction.

## Phase B — representation-repair history

Three additional resolved episodes are then supplied, one for each known evidence action.

They preserve the stable paired-measurement relations but permute the `surface_hint` association.

A successful repair process should therefore revise away from the previously rewarded surface features toward relations that remain invariant across acquisition and repair episodes.

## Held-out evaluation

Four frozen held-out cases are evaluated both before and after Phase B:

| Case | Stable raw relation | Misleading surface cue | Correct evidence |
| --- | --- | --- | --- |
| `R_DEP` | pair 0 is `close` | resembles the topology history | `independence_probe` |
| `R_PAY` | pair 1 is `far` | resembles the dependency history | `payoff_regime_probe` |
| `R_NET` | pair 2 has `sign_disagree` | resembles the payoff history | `topology_probe` |
| `R_NOVEL` | none of the learned relations activate | resembles a known history | `model_disrupting_probe` |

The held-out prediction/outcome values are also chosen to be nearest to the wrong resolved episode under compressed prediction/outcome/error similarity.

## Systems

### A. Compressed outcome memory

Persists only:

```text
prediction
outcome
absolute error
resolving probe
```

and retrieves the nearest historical episode.

### B. Fixed typed oracle

Uses the three correct relational distinctions from the start:

```text
pair0_close
pair1_far
pair2_sign_disagree
```

This is an upper-bound control, not a learnable baseline.

### C. Adaptive representation learner

Starts from the frozen candidate library, learns a probe-specific representation from Phase A, receives the Phase B failures/resolutions, re-learns under the same rule, and is then evaluated again.

No semantic causal labels are provided during either fit.

## Metrics

Report separately; no composite score:

```text
pre_repair_held_out_selection_rate
post_repair_held_out_selection_rate
Q_repair = post - pre
representation_change_rate
post_repair_novel_model_check_rate
post_repair_false_model_check_rate
selected_representation_cost
compressed_baseline_rate
fixed_oracle_rate
```

Also report the selected candidate relation for each known probe before and after repair.

## Primary hypothesis

A successful representation-repair result requires all of:

```text
pre_repair_held_out_selection_rate < post_repair_held_out_selection_rate
Q_repair > 0
post_repair_novel_model_check_rate = 1
post_repair_false_model_check_rate = 0
```

## Primary null

```text
H0:
post_repair adaptive representation learner
<= its own pre-repair performance
```

A secondary comparison asks whether the repaired learner approaches the fixed typed oracle.

## Interpretation constraints

A positive result would support only:

> In this synthetic benchmark, a learner can recover a more transferable representation from raw resolved histories after a previously rewarded surface abstraction fails.

It would not establish:

- unrestricted discovery of new variables;
- a uniquely negative-space mechanism;
- that the candidate relation library is minimal or domain-general;
- that the learner invented the relation operators themselves;
- real-world transfer;
- robustness to noisy resolution labels;
- superiority over modern learned-representation methods.

If the adaptive learner succeeds, the next attack should remove or expand the frozen candidate relation library rather than add more theory primitives.

## Failure-preserving rule

The case matrix, candidate library, objective, thresholds, and metrics are frozen before policy implementation. Do not alter them after observing the first CI result; any repair belongs in a later version.
