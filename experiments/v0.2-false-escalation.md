# v0.2 Preregistration — False Escalation

Status: **registered before execution**

## Research question

Can a history-aware negative-space search policy distinguish repeated failure caused by model inadequacy from repeated failure caused by ordinary noise/low power, under matched surface conditions and evidence costs?

## Primary hypothesis

The v0.2 candidate should improve **escalation calibration** relative to the frozen v0.1.1 `causal_negative_space_search` policy:

```text
higher or equal true escalation on model-inadequate cases
AND
lower false escalation on adequate-but-noisy cases
```

The main scientific comparison remains the strongest matched general causal policy with access to the same history.

## Null

```text
history_aware_negative_space_search
<= history_aware_general_causal_reasoner
```

on held-out evidence selection under matched information and cost.

If the strong causal policy matches or exceeds the negative-space policy, v0.2 does not establish incremental value for explicit negative-space structure.

## Cases

Construct paired families with equal obvious failure counts but different failure structure.

### Model-inadequate cases

History contains systematic residual structure incompatible with the supplied hypothesis family.

Expected evidence action:

```text
model_disrupting_probe
```

### Adequate-but-stubborn cases

History contains failures compatible with noise, weak effect, or low power inside the supplied model.

Expected evidence action:

```text
targeted_within_model_probe
```

## Held-out requirement

At least half of scored cases are held out from the hand-tuned development signatures and vary surface capability, failure count, residual magnitude, variance, and probe cost.

The v0.2 result must report development and held-out performance separately.

## Metrics

Report without a composite score:

```text
true_escalation_rate
false_escalation_rate
correct_evidence_selection_rate
post_evidence_regime_interpretation_rate
evidence_cost
held_out_correct_evidence_selection_rate
```

## Required controls

- `causal_negative_space_search` from v0.1.1, unchanged;
- `general_causal_reasoner` from v0.1.1, unchanged;
- a history-aware strong general causal competitor;
- the v0.2 history-aware negative-space candidate;
- naive controls where informative.

## Interpretation constraints

A positive result does not show that negative-space search improves causal interpretation if both strong policies interpret supplied evidence equally well.

A result where the v0.2 candidate beats the frozen v0.1.1 policy but not the history-aware causal baseline supports only:

> structured failure history improves search control.

It does not support:

> explicit negative-space structure adds value beyond strong causal reasoning.

A false-escalation reduction must not be purchased by never escalating.

## Negative-result rule

Do not modify the benchmark cases or scoring after seeing the first CI result. Preserve any failure before policy repair. A follow-up policy change requires a new experiment/version.
