# v0.6 Preregistration — Construction-Language Boundary

Status: frozen before v0.6 learner implementation.

## Research question

Can a solver recognize when its **current construction language** is non-identifying, rather than responding by either forcing a current explanation or merely abstaining?

The target transition is:

```text
resolved history
-> map through current language
-> detect conflicting labels inside one language-equivalence class
-> diagnose language inadequacy
-> request language expansion
```

The experiment does not attempt operator invention.

## H1 — the hostile pair is language-equivalent

For matched `order_up_probe` and `order_down_probe` episodes:

```text
phi_L(up) = phi_L(down)
```

for every expression in the frozen v0.5 construction language.

The matched episodes differ only in raw `ordered_trace` structure that the current language cannot inspect.

## H2 — the boundary is recoverable from raw data

A fixed oracle supplied with trace-direction predicates will separate the two classes from the same raw records.

This distinguishes construction-language insufficiency from absence of discriminating information in the observation record.

## H3 — boundary diagnosis beats false assimilation

The boundary-aware auditor will classify the held-out order cases as:

```text
language_status = inadequate
selected_probe = language_expansion_probe
```

The current-language assimilator will force at least one existing order class and therefore fail the nonhallucination criterion.

## H4 — boundary diagnosis is stronger than blind abstention

The conservative abstainer may avoid a false class assignment but will report:

```text
language_status = unknown
```

on the hostile pair.

The boundary-aware auditor must report `inadequate`, demonstrating that it identifies *why* the current evidence cannot resolve the case.

## H5 — uncertainty is not automatically language failure

A held-out signature with no resolved historical match and no demonstrated conflicting equivalence class must be reported as:

```text
language_status = unknown
```

not `inadequate`.

## Frozen current language

Exactly:

```text
all v0.4 single relations
+
all pairwise AND expressions from v0.5
```

No expansion of this language is allowed after seeing CI results.

## Frozen raw extension

v0.6 adds one raw field:

```text
ordered_trace: tuple[float, ...]
```

The primary current-language systems do not possess an operator that reads this field.

The oracle alone receives:

```text
trace_increasing
trace_decreasing
```

These operators are fixed before execution and exist solely as a recoverability control.

## Frozen outputs

For each held-out case:

```text
selected_probe
language_status
matched_resolving_probes
```

`language_status` is an evaluation label, not a frozen-core primitive.

## Frozen held-out classes

```text
H_COMP       # current language adequate through composition
H_REF        # current language adequate through a supplied relation
H_ORDER_UP   # hostile language-inadequate case
H_ORDER_DOWN # hostile language-inadequate case
H_UNKNOWN    # unsupported but not demonstrated inadequate
```

## Primary metrics

No composite score. Report:

- language-inadequacy detection;
- false inadequacy;
- boundary nonhallucination;
- adequate-case selection;
- unknown calibration;
- language-expansion requests;
- false language-expansion requests;
- oracle recoverability;
- current-language expression count.

## Claim if positive

> The system can recognize a demonstrated non-identifiability boundary of its current construction language and distinguish it from ordinary unsupported uncertainty, without being supplied a replacement-operator search menu.

## Claim if null

If the hostile pair is distinguishable under the frozen language, if the auditor cannot separate `inadequate` from `unknown`, or if the result requires adding an operator to the primary learner after execution, record the null. Do not enlarge the language to rescue v0.6.

## Scope brake

A positive result is **boundary detection only**.

It must not be described as:

```text
operator invention
language synthesis
interface invention
```

The next experiment may attempt operator discovery only after this boundary-detection capability is independently established.
