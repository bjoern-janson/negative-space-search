# v0.7 Operator-Discovery Preregistration

Status: **frozen before implementation**

## Question

After a demonstrated v0.6 construction-language collision, can a system repair its language by synthesizing a new transferable abstraction from a primitive substrate when the useful full operator is not supplied as a candidate?

The benchmark separates:

1. boundary detection;
2. abstraction synthesis;
3. held-out transfer;
4. timing/economy of synthesis.

It does **not** treat a synthesized abstraction as epistemic authority. A new expression is only a candidate coordinate used to improve evidence selection.

## Frozen distinction

`operator search` means selecting a ready-made semantic operator from a supplied list.

`operator construction` in v0.7 means generating a new expression tree from generic primitive operations. No list containing the target full predicates is supplied.

v0.7 still does **not** establish unrestricted primitive invention because the primitive substrate and expression grammar are supplied.

## Primitive substrate R

Each episode contains the v0.6 raw fields plus an ordered trace of length four.

The synthesizer may inspect the trace only through generic terminals and operations:

- indexed scalar terminals: `t0`, `t1`, `t2`, `t3`;
- scalar constants: `0.0`, `0.5`, `1.0`;
- arithmetic constructors: `ADD(x,y)`, `SUB(x,y)`;
- comparison constructors: `GT(x,y)`, `LT(x,y)`.

No semantic operators such as `trace_increasing`, `trace_decreasing`, `endpoint_direction`, `center_heavy`, `edge_heavy`, `frequency`, `phase`, or `dependency` are supplied.

Numeric expression depth is capped at one arithmetic constructor. Predicates compare generated numeric expressions. This creates a finite generic program space while withholding the useful full abstractions.

## Current construction language L_t

The frozen v0.6 current language remains exactly the v0.5 family:

- v0.4 primitive relations over paired measurements;
- every pairwise `AND` composition of those relations.

It contains 78 expressions and cannot inspect trace order or trace-position arithmetic.

## Two hostile collision families

The benchmark contains two independent current-language equivalence classes.

### Family D — endpoint direction

Two resolving classes share the same full 78-expression current-language signature.

Their raw traces differ such that a transferable discriminator can be constructed from indexed trace values. The useful full predicate is not supplied.

### Family C — center/edge relation

Two different resolving classes share another full current-language signature.

Their raw traces require a different synthesized relation involving arithmetic over multiple trace positions. This prevents v0.7 from reducing to one hard-coded order heuristic.

## Controls

The benchmark also contains:

- current-language-adequate classes that require no synthesis;
- an unsupported `unknown` signature with no demonstrated historical collision;
- held-out traces whose surface values differ from training examples.

Unknown is not equivalent to language inadequacy.

## Systems

### 1. Current-language assimilator

Frozen v0.6 false-assimilation control. It forces an existing class in a collision.

### 2. Conservative abstainer

Frozen v0.6 nonhallucinating control. It reports ordinary unknown rather than diagnosing/repairing the language.

### 3. Boundary-only auditor

Frozen v0.6 boundary detector. It correctly identifies collision classes but stops at `language_expansion_probe`.

### 4. Always-expand generic synthesizer

Uses the generic expression generator for every resolved probe class, regardless of whether the current language is adequate.

This is the strong generic feature-synthesis / search-without-boundary baseline.

### 5. Boundary-gated generic synthesizer

Uses exactly the same generator, scoring rule, primitive substrate, search budget per invoked class, and complexity penalty as the always-expand baseline.

It invokes synthesis only for current-language equivalence classes that contain conflicting resolved outcomes.

Any performance tie with lower search cost supports timing/economy, not better invention quality.

## Synthesis scoring

For each target resolving class within a collision, candidate predicates are scored one-vs-rest inside that collision class.

Primary objective:

`balanced_accuracy - complexity_penalty * expression_complexity`

Frozen constants:

- required training balanced accuracy for a repair: `1.0`;
- complexity penalty: `0.002`;
- each candidate evaluation costs one search unit.

Ties are resolved by lower complexity, then lexical expression name.

A synthesized operator is retained only if it separates its target class perfectly on the resolved training histories in that collision.

## Primary metrics

No composite score.

- `boundary_detection_rate`
- `construction_success_rate`
- `held_out_repair_selection_rate`
- `multi_family_transfer_rate`
- `false_expansion_rate`
- `adequate_case_preservation_rate`
- `unknown_calibration_rate`
- `search_cost`
- `representation_cost`
- `generated_operator_count`

## Q_invention operationalization

For this finite benchmark only:

`Q_invention = P(held-out discrimination improves | retained abstraction was generated from primitives and was not a supplied full predicate)`

This is an evaluation dimension, not a new architectural primitive.

## Primary hypotheses

### H1 — construction-language repair

The boundary-gated synthesizer will generate at least one retained predicate for each hostile collision family and achieve perfect held-out selection on both families.

### H2 — current-language failure

The current-language assimilator will false-assimilate at least one hostile held-out case.

### H3 — abstention is weaker than repair

The conservative abstainer and boundary-only auditor will avoid false causal assimilation but will not resolve the hostile held-out classes.

### H4 — gating improves economy, not generator quality

The always-expand and boundary-gated synthesizers will use the same synthesis algorithm and are expected to match on hostile held-out accuracy.

The boundary-gated system should incur strictly lower synthesis search cost by not expanding current-language-adequate classes.

### H5 — no false language inflation

Boundary gating must not synthesize new operators for adequate or unsupported-unknown signatures.

## Nulls

A failure to synthesize transferable operators means v0.6 boundary detection has not yet been converted into construction-language repair.

If always-expand generic synthesis matches the boundary-gated system at equal cost, there is no evidence that boundary diagnosis improves representational economy.

If a simpler supplied expression already resolves the hostile classes under the frozen current language, the benchmark is invalid.

## Explicit nonclaims

v0.7 does not establish:

- invention of the primitive substrate;
- invention of the synthesis grammar G;
- open-ended program synthesis;
- autonomous discovery of new raw sensors;
- causal truth of a synthesized expression;
- unique value of negative-space terminology;
- superiority over all AutoML, feature-learning, or program-synthesis systems;
- robustness to corrupted resolving labels;
- real-world scientific concept invention.

## Language-model baseline

A genuine language-model abstraction baseline is intentionally **not** simulated with a hand-written proxy in deterministic CI. Such a comparison should use an actual frozen model/version and exported benchmark data in a separate reproducible run. v0.7 therefore makes no claim against LLM-based semantic synthesis.

## Success interpretation

The strongest permitted positive interpretation is:

> After a demonstrated construction-language collision, a system can conditionally invoke a generic expression synthesizer, construct previously unsupplied full predicates from a supplied primitive substrate, and improve held-out discrimination while avoiding synthesis cost on already-adequate regions.

This would demonstrate construction-language repair inside a supplied meta-language. It would not demonstrate unrestricted interface invention.
